# `docs/old` audit: coverage and code verification

Audit of the three superseded guides in `docs/old/` against:

- the current docs: `docs/README.md`, `docs/protocols/openai-responses.md`, `docs/protocols/openai-chat-completions.md`, `docs/protocols/anthropic-messages.md`;
- the canonical maintenance homes the reorg re-pointed them at: `python/ARCHITECTURE.md`, `python/CONVENTIONS.md`, `tests/cassettes/README.md`, and the matcher-script docstrings;
- the current implementation in `python/molto/`.

Old files audited:

- `docs/old/message-boundaries.md` (304 lines, "investigation snapshot as of 2026-08-18")
- `docs/old/openai-responses-anthropic-messages-parity.md` (300 lines)
- `docs/old/openai-responses-cc-parity.md` (370 lines)

The reorg happened in `3d6d11d` ("docs: Reorganize protocol guides and correct translation contracts", PR #54). One later functional commit, `1294ada` (PR #55, native-path error translation), invalidated more `docs/old` text.

Status codes used below:

- **Present** – statement carried into a current doc (possibly re-worded/re-pointed).
- **Relocated** – carried into a canonical non-`docs/` home (architecture, conventions, cassette policy, matcher docstring).
- **Condensed** – survives, but a qualifier or reason is gone.
- **Missing** – no equivalent statement anywhere in the current docs or canonical homes.
- **Stale** – the old claim is no longer true of the code; the current docs are correct.

## Verdict

Coverage is **substantially faithful on correctness**: every code-verifiable behavior statement in `docs/old` that survives into the current docs is accurate, and the reorg correctly rewrote at least seven old claims that the code had already overtaken (§6).

The real problem is **coverage, not accuracy**, and it is bigger than the previous notes recorded:

1. Six consolidated cross-protocol views were deleted rather than re-hosted (§4 A1–A6). All of their individual facts exist somewhere, but the cross-protocol comparison — the reason the two `*-parity.md` files existed — is gone.
2. Three forward-looking sections were deleted outright: the boundary-fidelity "Architecture implications", the "Values That Must Be Generated" enumeration, and the documented-test-gaps list is now both incomplete and partly wrong (§4 A3, §7 B1).
3. Two caller-relevant safety rules were dropped from all docs: "applications must not inspect or synthesize these [opaque] values" and the same-provider issuance rule survives only as prose in guides that no longer state the prohibition (§4 A7).
4. Matched-fixture knowledge regressed: the old scenario descriptions, the `reasoning_raw` → `provider="vllm"` filename mechanism, and the helper-file list (`python/molto/utils/test.py`, `tests/test_match_*.py`, `tests/utils/test_test_utils.py`) now appear **only** in `docs/old/` (§4 B2–B4).
5. `docs/old/` itself is now a trap: unreferenced, unlabelled, and containing eight broken links plus statements the code contradicts (§8).
6. Six implementation behaviors are documented nowhere — not in the old docs either — including a whole model-gating heuristic and a silent event-ignore path (§7).

Recommended work is in §9; the two highest-value items are the Messages→Responses thinking mapping (A1, a documented contract the code implements and the guides omit) and adding a superseded banner + link fix to `docs/old/` (C1).
